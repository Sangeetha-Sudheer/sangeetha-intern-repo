# AI Usage Guidelines

## AI Tools Commonly Used in My Role

As a Backend Developer Intern, AI tools can help with tasks such as:

- explaining unfamiliar code;
- suggesting debugging approaches;
- generating examples of unit tests;
- helping understand error messages;
- summarising technical documentation;
- improving technical writing and reflections;
- suggesting API, database, or backend implementation ideas;
- reviewing code for possible issues.

AI can be useful for speeding up learning and helping me explore possible solutions, but I should still understand and verify the work myself.

## Benefits of Using AI in a Professional Setting

AI tools can improve productivity by helping with repetitive or time-consuming tasks.

Some benefits include:

- faster research;
- quicker explanations of technical concepts;
- support when debugging;
- help generating initial code examples;
- help improving documentation;
- assistance with brainstorming possible solutions.

AI can also help me learn by explaining why a particular approach works.

## Risks of Using AI

AI-generated content may be incorrect, outdated, incomplete, or unsuitable for the project.

There is also a risk of exposing confidential information if sensitive company data, credentials, source code, customer information, or private project details are entered into an AI tool.

Another risk is becoming too dependent on AI and accepting suggestions without understanding them.

For these reasons, AI output should always be reviewed critically.

## Information I Should Never Enter Into AI Tools

I should never enter confidential or sensitive information unless the company has explicitly approved the tool for that information.

Examples include:

- passwords;
- API keys;
- access tokens;
- encryption keys;
- customer personal information;
- private company data;
- confidential business information;
- production credentials;
- internal security information;
- private source code if company policy does not allow it.

Before sharing any information with an AI tool, I should consider whether the information is public, confidential, or sensitive.

## How I Can Fact-Check AI-Generated Content

I should not assume that an AI-generated answer is correct.

I can validate AI output by:

- checking official documentation;
- running and testing generated code;
- comparing the answer with trusted technical sources;
- reviewing the logic myself;
- checking whether APIs, libraries, or commands actually exist;
- asking a teammate or mentor when the information is important or unclear.

For code, the most important validation is to run tests and inspect the result.

## When Should I Use AI and When Should I Rely on My Own Skills?

I should use AI as a support tool when I need help understanding a concept, exploring possible solutions, debugging an issue, or improving documentation.

I should still rely on my own skills to understand the final solution, make technical decisions, and verify whether the result is correct.

If I cannot explain what the AI-generated code is doing, I should not use it without further investigation.

AI should assist my work rather than replace my own reasoning.

## How I Can Avoid Over-Reliance on AI

I can avoid over-reliance by:

- trying to understand the problem before asking AI;
- reviewing every suggestion instead of copying it automatically;
- testing generated code;
- checking official documentation;
- writing parts of the solution myself;
- asking why a solution works;
- using AI to learn rather than only to produce answers.

This helps me continue developing my own technical skills.

## Data Privacy When Using AI Tools

To protect data privacy, I will:

- avoid entering passwords, tokens, or credentials;
- remove personal or confidential information from prompts;
- avoid sharing private company information unless approved;
- use examples or anonymised data when possible;
- follow Focus Bear's policies about approved AI tools;
- check the information before submitting it to an AI service.

If I am unsure whether information is safe to share, I should ask before using it in an AI tool.

## Task I Improved Using an AI Tool

One task I used AI to help improve was debugging and writing backend unit tests.

I used AI to help me understand how to structure NestJS controller tests and how to mock service dependencies.

The AI-generated suggestions gave me a useful starting point, but I still needed to compare them with my actual controller methods, modify the examples, run the Jest tests, and fix any issues.

This made the task faster while still requiring me to understand and verify the implementation.

## Critical Review of the AI-Generated Output

The AI-generated output required checking and editing.

For example, generated code may use method names, data structures, or assumptions that do not exactly match the project.

I reviewed the generated test code against my existing NestJS files and changed it to match the actual methods in the project.

I then ran the tests to confirm that the final version worked correctly.

This showed me that AI output should be treated as a suggestion rather than automatically trusted.

## Best Practice I Will Follow at Focus Bear

One important best practice I will follow is:

**Never submit or use AI-generated work without reviewing, understanding, and validating it first.**

I will also avoid entering confidential information into AI tools and will follow company guidance about which tools and information are approved.

## Reflection

AI can be very useful for learning, debugging, brainstorming, and improving productivity.

However, I am responsible for the final work I submit.

I need to use critical thinking, protect company and user data, test AI-generated code, and make sure I understand the solution.

The best way for me to use AI is as an assistant that supports my learning and problem-solving rather than as a replacement for my own judgement.
